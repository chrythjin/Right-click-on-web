# v0.5.0 사후 코드 검토 및 수정

**날짜**: 2026-08-09 (KST)
**범위**: 완료된 v0.5.0의 storage, 모드 전환, QA 문서 정합성 검토
**상태**: 구현 및 자동 검증 완료 / 실제 Chrome 수동 QA 필요

## 확인 및 수정

- 활성 unlocker에서 Lite와 Ultimate를 전환해도 선택 CSS가 즉시 갱신되도록 `content.js`의 `setEnabled()`를 보완했습니다.
- Chrome Sync quota fallback으로 local에 기록된 최신 선택이 오래된 sync 값을 이기도록 fallback 키 표식을 추가했습니다. 이후 sync 저장이 성공하면 해당 표식을 제거합니다.
- 기본값 객체를 `chrome.storage.get()`에 전달해 빈 sync 저장소가 local 설정을 덮을 수 있던 읽기 경로를 키 배열 읽기로 교정했습니다.
- 업데이트 시 local에서 sync로 옮긴 legacy boolean domain 설정도 sync와 local 양쪽에서 `{ enabled, mode }` 객체로 정규화하도록 마이그레이션 순서를 보장했습니다.
- 수동 QA 페이지에 Lite 전용 `user-select: none` 표면을 추가하고, `chrome.storage.session`이 새로고침이나 탭 닫기로 지워진다는 잘못된 설명을 브라우저 세션 종료 시 해제로 수정했습니다.
- HTTP(S) URL에서만 도메인/세션 설정이 해석된다는 계약에 맞춰 QA 안내에서 `file://` 직접 열기를 제외했습니다.
- 도메인 항목이 아직 없을 때 Lite 또는 Ultimate를 선택하면 UI 안내대로 `{ enabled: true, mode }` 항목을 생성하도록 팝업 저장 경로를 바로잡았습니다. 기존 도메인 항목의 명시적 ON/OFF 값은 그대로 유지됩니다.

## 검증

- JavaScript 구문 검사: `shared.js`, `background.js`, `content.js`, `content-main.js`, `popup.js` 통과.
- Manifest V3와 dual-script 순서 계약 통과.
- Node 기반 Chrome storage 모의 검증: quota fallback 최신 local 값 우선, sync 복구, legacy 설정 sync/local 정규화 통과.
- Node 기반 DOM 모의 검증: 활성 Lite → Ultimate → Lite 전환에서 선택 CSS가 즉시 추가·제거되는 것 확인.
- Node 기반 팝업 모의 검증: 기본 도메인에서 Lite 클릭 시 활성 Lite 도메인 항목이 sync 저장소에 생성되는 것 확인.
- 실제 unpacked Chrome 확장 검증은 현재 환경의 Chrome 프로필 정책 때문에 자동화하지 못했습니다.

## 후속 수동 QA

테스트 페이지를 HTTP(S)로 제공해 연 뒤 unpacked 확장을 로드하고, 섹션 9~11에서 도메인 토글, 세션 유지, Lite/Ultimate 선택 가능 여부를 확인합니다.
