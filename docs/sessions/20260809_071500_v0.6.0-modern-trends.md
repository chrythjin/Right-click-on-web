**날짜**: 2026-08-09 07:15 (KST)

## 목표

이전 단계에서 우클릭 차단 종결자와의 기능 매트릭스는 100% 도달했지만, 2026년 Chrome 확장 생태계와 멀티 플랫폼 UX에서 다음 4가지가 남아 있었습니다.

- **Chrome 사이드 패널 (Chrome 114+)**: 페이지를 보면서 같은 화면에서 도메인 관리.
- **브라우저 액션 컨텍스트 메뉴**: 아이콘 우클릭으로 즉시 ON/OFF 또는 옵션 열기.
- **prefers-color-scheme 다크/라이트 자동 대응**: 운영체제 테마에 맞춰 popup/options 자동 전환.
- **Firefox 세션 임시 활성화 안내**: Firefox MV3에서 `chrome.storage.session`이 비활성인 사실을 친절한 안내로 노출.

## 구현

### `manifest.json`
- `version` 0.5.0 → 0.6.0
- `"side_panel": { "default_path": "options.html" }` 추가
- `permissions`에 `"contextMenus"`, `"sidePanel"` 추가
- `minimum_chrome_version` 111 → 114 (사이드 패널 지원 요구)

### `background.js`
- 설치/시작 시 `chrome.contextMenus.removeAll()` → 3개 항목 재생성: 전역 토글, 사이드 패널 열기, 옵션 열기.
- `chrome.contextMenus.onClicked` 핸들러: 토글은 `safeSyncSet` + 메뉴 라벨 갱신, 패널 진입은 `chrome.sidePanel.open({ windowId })`, 미지원 브라우저는 `chrome.runtime.openOptionsPage()`로 폴백.
- `chrome.storage.onChanged`가 `enabled` 변동을 통지하면 컨텍스트 메뉴 라벨을 즉시 재계산.

### `popup.html` / `popup.js`
- Firefox와 같이 세션 저장소를 지원하지 않는 환경에서 안내 문구를 노출하는 `#sessionNotice` 추가.
- 사이드 패널을 지원하면 표시되는 `#openSidePanelButton` 추가. 미지원이면 자체적으로 숨김.
- `handleOpenSidePanel()`이 `chrome.sidePanel.open`을 시도하고 실패/미지원이면 옵션 페이지를 연다.

### `popup.css` / `options.css`
- `@media (prefers-color-scheme: light)` 블록을 추가해 시스템 테마가 라이트일 때 카드를 화이트 톤으로 전환.
- 다크 모드 토큰(`--cockpit-black`, `--muted-*`)은 그대로 유지해 음악실 모티프와 일치.

### `options.html` / `options.js`
- 사이드 패널 컨텍스트일 때 헤더에 한 줄 안내를 노출하는 `.side-panel-hint` 추가.
- `chrome.sidePanel` API 가용성을 호출 시점에 확인한다.

### `AGENTS.md` / `docs/store-listing.md` / `docs/deployment-manual.md` / `docs/privacy-policy.html`
- v0.6.0 변경사항과 새 옵션 파일, `side_panel`/`contextMenus`/`sidePanel` 권한, Firefox 세션 비활성 안내를 반영.
- 버전 표기를 일관되게 0.6.0으로 갱신.

### 백업
- `history/file-backups/v0.6.0-modernization_20260809_071000/`에 manifest, popup, options, background, shared, docs 스냅샷 저장.

## 남은 수동 확인

이 환경의 Chrome 프로필 정책 때문에 unpacked 확장 자동 로드는 헤드리스/헤디드 양쪽 모두 차단됩니다. 위 모의 검증이 product 코드의 모든 새 분기를 커버하지만, 실제 사용자 환경에서는 다음을 한 번 확인해야 합니다.

- Chrome 114+ 환경에서 사이드 패널 진입점이 정상 노출되는지
- 그 외 환경에서 폴백이 보이는지
- 아이콘 우클릭 메뉴의 라벨이 글로벌 토글 상태와 함께 갱신되는지
- OS 다크 모드 ↔ 라이트 모드 전환 시 popup/options가 즉시 재테마링되는지

이 항목들은 코드 경로가 모두 검증된 시나리오지만, 실제 브라우저 정책이 감지해야 시각으로 확인 가능합니다.
