## 1. 목표

사용자 가치:
- **Ultimate 모드** (기본, 기존 동작): MAIN world 패치 + ISOLATED CSS `user-select: text !important` 주입 + 오버레이 무력화 + IDL 락 해제. 페이지의 모든 우클릭/선택/복사/드래그 차단을 완화.
- **Lite 모드**: MAIN world 패치 + ISOLATED capture-phase 인터셉터 + 오버레이 무력화. **CSS 주입 안 함** → 페이지의 `user-select: none`이 살아있어 시각적/구조적 변경 최소화.

차이점 정리:
| 동작 | Lite | Ultimate |
|:---|:---:|:---:|
| MAIN world `addEventListener` 패치 | ✅ | ✅ |
| MAIN world `attachShadow` 패치 | ✅ | ✅ |
| ISOLATED capture-phase 인터셉터 | ✅ | ✅ |
| 오버레이 무력화 (pointer-events) | ✅ | ✅ |
| CSS `user-select` 강제 주입 | ❌ | ✅ |
| IDL 락 해제 | ✅ | ✅ |

→ Lite는 페이지의 user-select 스타일은 보존하면서 우클릭·복사·드래그만 풀어줌.

## 2. 스키마 변경

### 이전 (v0.4.0)
```js
domainSettings = {
  "github.com": true,
  "example.com": false,
  "news.ycombinator.com": true
}
```

### 이후 (v0.5.0)
```js
domainSettings = {
  "github.com": { enabled: true, mode: "ultimate" },
  "example.com": { enabled: false, mode: "ultimate" },
  "news.ycombinator.com": { enabled: true, mode: "lite" }
}
```

## 3. 스키마 마이그레이션 규칙

`parseDomainSetting(value)` 진리표 (5-케이스):

| 입력 | 결과 |
|:---|:---|
| `true` | `{ enabled: true, mode: "ultimate" }` |
| `false` | `{ enabled: false, mode: "ultimate" }` |
| `{ enabled: true, mode: "lite" }` | `{ enabled: true, mode: "lite" }` |
| `{ enabled: false, mode: "ultimate" }` | `{ enabled: false, mode: "ultimate" }` |
| `{ mode: "unknown_mode" }` | `{ enabled: true, mode: "ultimate" }` (fallback) |
| `null`, `undefined`, `'string'`, 그 외 | `{ enabled: false, mode: "ultimate" }` |

**마이그레이션 트리거**: `background.js`의 `chrome.runtime.onInstalled`에서 `reason === 'update'` 일 때.

**idempotency**: `JSON.stringify` 비교로 변경 없으면 set() 호출 안 함. 사용자 storage가 이미 v0.5.0 형식이면 추가 쓰기 없음.

## 4. 구현 세부

### 4.1 shared.js (신규 export)
- `MODE_LITE = 'lite'`
- `MODE_ULTIMATE = 'ultimate'`
- `DEFAULT_MODE = 'ultimate'`

- `parseDomainSetting(value)` — 진리표대로 변환

- `isDomainEnabled(...)` — 객체/boolean 모두 허용 (v0.5.0 객체 + v0.4.0 boolean 모두)
- `normalizeDomainSettings(s)` — 전체 entry 일괄 변환

### 4.2 background.js
- `migrateDomainSettings()` 신설

- `resolveEnabled()` 반환값에 `mode` 필드 추가
- `createStats()`에 `mode` 필드 추가

### 4.4 popup.html / popup.css
- `.mode-card` (mode-toggle 라디오 그룹) + `.mode-hint` 추가
- `.mode-button` / `.mode-button.is-active` / `.mode-button:focus-visible` / `.mode-button:disabled` 스타일

### 4.5 popup.js
- state에 `domainMode` + `effectiveMode` 추가
- `handleModeSelect(mode)` 신설

  - 도메인 entry가 있을 시 `enabled` 유지 + `mode`만 변경
- `render()`에 mode-card UI 갱신 로직
  - session active 시 mode 버튼 disabled
  - hint 텍스트 동적 변경 (Lite/Ultimate/session/no-entry)

## 8. 알려진 한계

- MAIN world 패치는 document_start 1회 적용 후 되롤 수 없음. Lite/Ultimate 토글은 즉시 CSS 주입 여부만 영향. 페이지 reload 시 MAIN world 재적용 (항상 양쪽 모드 모두).
- Lite는 페이지의 `user-select: none` 우클릭 방어 외 다른 CSS 차단 패턴 (예: `pointer-events: none`으로 우클릭만 차단)에는 효과 없음. 이런 사이트는 Ultimate 필요.
- 도메인 entry가 없을 때 Lite 선택은 enabled=true로 자동 생성 + mode 저장. 의도된 동작이지만 UI에서 명시적으로 안내 (mode-hint 텍스트).
