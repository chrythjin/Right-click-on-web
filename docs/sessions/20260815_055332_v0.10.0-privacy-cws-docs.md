# v0.10.0 개인정보 및 CWS 문서 갱신

## 목적

작업 3.1~3.4에서 구현·자동 검증된 이미지 OCR, 선택형 로컬 OCR 기록, 마지막 수동 영역 반복의 데이터 처리 계약을 공개 개인정보처리방침과 Chrome Web Store 유지보수 문서에 맞춘다. 이 기록은 로드맵의 작업 3.5 체크박스 상태를 변경하지 않는다.

## 문서화한 계약

- 화면 캡처 픽셀은 로컬 WASM OCR 처리 중 메모리에만 일시적으로 존재하며 저장하거나 전송하지 않는다. 원격 코드 로딩, 텔레메트리, 클라우드 OCR, 화면 콘텐츠 업로드가 없다.
- OCR 기록은 기본 OFF다. 사용자가 opt-in한 경우에만 `chrome.storage.local`에 최종 텍스트와 allowlisted `{ id, hostname, savedAt }`를 저장한다. 최신순 최대 20개, 최대 30일, 총 최대 64 KiB로 보존을 제한하며 동기화하지 않는다.
- 마지막 영역 반복은 `chrome.storage.session`에 tab ID, hostname, viewport, rect, DPR, source, timestamp만 보관한다. 이전 이미지 바이트와 OCR 텍스트는 보관하지 않고, tab/hostname/viewport/DPR/TTL/rect를 확인한 뒤에만 현재 화면을 새로 캡처한다.
- `storage`, `activeTab`, `contextMenus`, `sidePanel`, `offscreen`, `<all_urls>`의 실제 사용자 흐름과 역할을 CWS 문구에 대조했다. 단일 목적 문구는 막힌 웹 텍스트 복구와 선택 불가능한 화면 텍스트의 로컬 OCR 추출로 통일했다.
- 모든 패키징 문서는 manifest가 참조하는 OCR helper, content/overlay/offscreen 자산, 로컬 WASM·언어 모델을 포함하는 v0.10.0 명령으로 갱신했다.

## 검증

- `& .\scripts\verify.ps1 -RootPath (Get-Location)`를 실행하여 repository verifier를 확인했다.
- `git diff --check`를 실행하여 문서 변경의 whitespace 오류가 없음을 확인했다.
- 이 환경에는 승인·연결된 unpacked Chrome 대상이 없어 실제 Chrome에서 OCR, 기록 opt-in/out, 마지막 영역 반복을 수동 관찰하지 않았다. 해당 수동 QA는 별도의 릴리스 게이트다.

## 정합성 보정

- 개인정보처리방침의 저장 위치를 local, sync, session 세 영역으로 바로잡았다.
- 공개 정책 파일의 repository 존재와 공개 URL 접근성을 구분했다. GitHub Pages 활성화나 공개 URL 검증은 완료로 기록하지 않았으며 제출 전 게이트로 남긴다.
- 기존 `assets/screenshots/test-page.png` 1280×800 제출 이미지는 준비됨으로 유지하고, 새로운 v0.10.0 unpacked Chrome 흐름 캡처는 별도 수동 게이트로 분리했다.
- CWS 데이터 사용 설문의 “수집하지 않음/아니오”는 개발자·제3자 대상 외부 수집·전송 범위임을 명시하고, opt-in local-only OCR 기록의 존재를 함께 적었다.
- 개인정보처리방침 1절의 “수집하지 않습니다”도 개발자·제3자 외부 수집·전송 범위로 명시해, 처리 중 메모리의 OCR 픽셀과 local/sync/session 저장 상태를 부정하지 않도록 보정했다.
