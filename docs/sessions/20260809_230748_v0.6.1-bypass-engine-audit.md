# v0.6.1 최신 우회 기술 감사 및 호환성 보강

## User Request

코드 결함을 다시 검토하고 웹·GitHub의 최신 우회 기술 및 현재 브라우저 API와 비교해 필요한 기술을 적용한다.

## 확인된 문제

- MAIN-world 패처가 ISOLATED 스크립트 뒤에 선언되어 `document_start` 선점 계약이 불명확했다.
- `about:blank`, `data:`, `blob:` 계열의 관련 하위 프레임 주입 범위가 누락됐다.
- Firefox MV3가 `background.service_worker`만으로는 백그라운드 로직을 시작하지 못한다.
- 차단 listener를 sentinel로 교체한 뒤 원본 listener로 `removeEventListener()`를 호출하면 등록을 제거하지 못했다.
- Chrome의 `storage.session`은 기본 접근 수준에서 콘텐츠 스크립트가 읽지 못해 세션 우선순위가 무력화될 수 있었다.
- 문서 CSS는 Shadow DOM 경계를 넘지 못해 Ultimate 선택 CSS가 open Shadow Root 내부에 적용되지 않았다.
- 동적으로 추가된 노드 자체가 Shadow Host이면 탐색이 host를 건너뛰었고, 분리된 Shadow Root observer도 남을 수 있었다.
- `contenteditable="plaintext-only"` 요소를 편집 영역으로 인식하지 못했다.
- 저장소 변경이 resolve 중 연속 발생하면 마지막 변경을 놓칠 수 있었다.
- 관련 opaque frame에서 직접 hostname을 얻지 못하면 부모 도메인 OFF 정책 대신 전역 설정으로 떨어질 수 있었다.
- listener 옵션의 `capture` getter를 패처와 native 구현이 각각 읽어 부수 효과가 두 번 발생할 수 있었다.
- Shadow Root가 분리·재부착되면 observer/style 소유권이 유실되거나 다시 연결되지 않을 수 있었다.
- `storage.session.get`만 있는 Firefox형 API shape를 지원 가능으로 오판할 수 있었다.

## Changes

- `manifest.json`: v0.6.1, MAIN-first 순서, `match_about_blank`, `match_origin_as_fallback`, Chrome 121+, Firefox용 `background.scripts`를 선언했다.
- `background.js`: Chrome 서비스 워커와 Firefox 비영구 배경 스크립트에서 같은 파일을 사용하고, 설치/시작 시 `storage.session` 접근 수준을 콘텐츠 스크립트까지 확장한다.
- `shared.js`: `storage.session.get`과 콘텐츠 스크립트 접근 계약인 `setAccessLevel`이 모두 있을 때만 세션 모드를 지원 가능으로 판정한다.
- `content-main.js`: event type을 DOMString처럼 정규화하고 target/type/listener별 sentinel을 추적한다. 옵션 객체는 native 메서드에 그대로 한 번만 전달해 `capture` getter 의미론을 보존하면서 원본 listener로 정상 해제한다.
- `content.js`: `isContentEditable` 면제, Shadow Root별 Ultimate style/observer Map, 분리 sweep와 재부착 복구, 관련 opaque frame의 부모·referrer·blob origin hostname 상속, 연속 설정 변경의 후속 resolve를 추가했다.
- `tests/manual/blocked-page.html`: closed→open 변환과 Shadow 내부 `user-select` 상태를 함께 표시한다.

## Verification

- 변경 JavaScript의 LSP diagnostics 0건 및 `node --check` 통과.
- `git diff --check` 통과.
- 브라우저 엔진에서 차단 listener 미실행, 기본 동작 허용, String wrapper event type, closed→open Shadow Root를 확인했다.
- 브라우저 엔진에서 `contenteditable="plaintext-only"`의 paste listener 보존을 확인했다.
- 동적 Shadow Host에 Ultimate style이 주입되고 host 분리 후 observer가 해제됨을 확인했다.
- 서비스 워커 모의에서 install/startup 모두 `TRUSTED_AND_UNTRUSTED_CONTEXTS` 접근 수준을 설정함을 확인했다.
- 원본 listener로 `removeEventListener()`를 호출했을 때 동일 sentinel과 capture 값이 native 해제 호출에 전달됨을 확인했다.
- 설정 해석 도중 저장소 변경이 발생해도 후속 resolve가 실행되어 마지막 전역 OFF 상태가 반영됨을 확인했다.
- Chrome 151 실제 renderer에서 Firefox형/Chromium형 세션 capability가 각각 `false`/`true`로 판정됨을 확인했다.
- Chrome 151 실제 renderer에서 `addEventListener`/`removeEventListener`의 `capture` getter가 각각 정확히 1회 호출되고, 차단 listener는 0회 실행되며 같은 sentinel로 해제됨을 확인했다.
- 같은 `about:blank` frame에서 부모 도메인 OFF일 때 Ultimate style이 없고 전역 ON 대조군에서는 style이 존재해 opaque-frame 정책 상속을 확인했다.
- Shadow Host 분리 후 style 제거, 재부착 후 style 재주입, 재부착된 root 안의 새 차단 속성 제거를 Chrome 151에서 확인했다.
- v0.6.1 배포 문서와 공개 개인정보처리방침을 실제 권한·패키지 구성에 맞춰 갱신하고, `right-click-on-web-v0.6.1.zip`의 13개 필수 자산·루트 구조를 검증했다. 최종 ZIP은 35,491 bytes이며 SHA-256은 `556DD0F885E09A4C66C37F95126193866AAFF47D91D3A60390107146CF29972C`다.

## 조사 근거

- Chrome content scripts 문서: MAIN execution world와 관련 `about:`, `data:`, `blob:`, `filesystem:` frame에 대한 `match_origin_as_fallback` 계약을 확인했다.
  - https://developer.chrome.com/docs/extensions/reference/manifest/content-scripts
  - https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts#injecting-in-related-frames
- Chrome Storage API 문서: `storage.session`의 기본 접근 수준이 콘텐츠 스크립트를 제외하며 `setAccessLevel()`이 필요함을 확인했다.
  - https://developer.chrome.com/docs/extensions/reference/api/storage#property-session
- MDN Chrome incompatibilities 문서: Firefox의 content-script/background 실행 환경 차이를 교차 확인했다.
  - https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Chrome_incompatibilities
- uBlock Origin Lite의 `addEventListener-defuser` 구현은 native 참조를 먼저 캡처하고 필요한 listener만 선택적으로 무력화하는 보수적 패턴의 비교 기준으로 사용했다.
  - https://github.com/uBlockOrigin/uBOL-home/blob/main/chromium/rulesets/scripting/scriptlet/main/annoyances-overlays.addEventListener-defuser.js
- 공개 구현에서 발견한 MouseEvent 좌표 변조, Selection API 전역 무력화, `Event.prototype.preventDefault` 광역 교체는 정상 편집기·사이트 기능을 손상할 위험이 커 적용하지 않았다.

## 남은 표준상 한계

- 브라우저가 확장 주입 자체를 금지하는 특권 페이지, 스크립트 없는 sandbox frame, 이미 봉인된 cross-origin realm은 우회할 수 없다.
- DRM, canvas/image 텍스트, 서버가 전달하지 않은 콘텐츠는 DOM 기반 확장의 범위를 벗어난다.
- 전역 `preventDefault` 무력화나 debugger 탐지 교란은 정상 사이트 기능을 크게 훼손하므로 의도적으로 적용하지 않았다.
- 실제 unpacked Chrome/Firefox 프로필 자동 설치는 이 환경의 프로필 정책으로 막혀 기존처럼 수동 설치 QA가 남는다.
