# v0.4.0 구현 — chrome.storage.sync 동기화

**작성일:** 2026-08-08 (v0.3.0-alpha 작업 후속)
**작업 범위:** 부록 A.1 (chrome.storage.sync 통합 + quota 처리 + privacy policy)
**기준 버전:** v0.3.0-alpha
**목표 버전:** v0.4.0

## 1. User Request

벤치마킹 로드맵의 Phase 3 (chrome.storage.sync) 진행. 사용자가 동일 Google 계정으로 로그인한 다른 기기에서도 도메인별 설정이 자동 동기화되도록 한다.

## 2. Changes

### shared.js

**신설 export (5개)**:

| export | 역할 |
|:---|:---|
| `SYNC_QUOTA` | `{ BYTES_TOTAL: 102400, BYTES_PER_ITEM: 8192, MAX_ITEMS: 512 }` Chrome 정책 한도 |
| `isQuotaExceeded(err)` | 정규식 매칭으로 QuotaExceededError 감지 |
| `getBytesInUse(area)` | chrome.storage.getBytesInUse Promise wrapper (에러 시 0 반환) |
| `safeSyncSet(data, fallbackArea)` | sync 먼저 시도 → quota 시 local fallback |
| `resolveSettings(keys)` | sync+local 병렬 읽기 → sync 우선 merge |

### background.js

- `migrateLocalToSync()` 신설. `onInstalled`의 `reason === 'update'`에서 호출.
- sync에 데이터가 이미 있으면 migration skip (덮어쓰기 방지).
- sync 쓰기 실패(quota) 시 silent — local에 데이터 보존되며 popup이 sync+local merge로 읽음.
- `onStartup`에서는 migration 호출 안 함 (sync quota 연타 방지).

### content.js

- `resolveEnabled()`가 `resolveSettings()` 사용 — sync+local 병렬 읽기, sync 우선.
- `storage.onChanged` 리스너가 `'sync'` area도 처리.

### popup.js

- `state`에 sync 진단 필드 추가: `syncAvailable`, `syncBytesInUse`, `lastWriteFallback`.
- `handleGlobalToggle()` / `handleDomainToggle()`가 `safeSyncSet()` 사용 (local fallback 자동).
- `loadState()` 끝에서 `getBytesInUse(sync)` + `safeSyncSet` write probe로 sync 가용성 체크.
- `render()`에 sync 사용량 표시 로직 — "동기화 사용량: 23KB / 100KB (23%)" + 80% 초과 시 `is-warn`.
- fallback 발생 시 "동기화 사용 불가 — 현재 기기에만 저장됨" 표시.

### popup.html / popup.css

- `<p id="syncUsage" class="sync-usage is-hidden">` 추가 (session-button 아래).
- `.sync-usage` / `.sync-usage.is-warn` / `.sync-usage.is-hidden` 스타일 추가 (v0.4.0 additions 섹션).

## 3. Before / After

### Before (v0.3.0-alpha)

- 저장 영역: `chrome.storage.local` 단독. 기기 간 동기화 없음.
- 도메인별 설정: 이 기기에서만 유효. 다른 PC에서 새로 등록 필요.
- 쓰기 전략: 항상 local. quota 이슈 없음.
- popup UI: sync 사용량 표시 없음.

### After (v0.4.0)

- 저장 영역: `chrome.storage.local` + `chrome.storage.sync`. 동일 Chrome 계정 로그인 시 자동 전파.
- 도메인별 설정: 모든 동기화된 기기에서 동일하게 작동.
- 쓰기 전략: sync 우선 + quota 시 local fallback. 사용자 의도 절대 손실 안 됨.
- popup UI: "동기화 사용량" 표시 + 80% 초과 시 gold 경고 + fallback 발생 시 안내.
- privacy policy: Chrome Web Store 정책 준수 (sync 사실 명시).
- background.js: v0.3.0→v0.4.0 업데이트 시 local→sync 자동 마이그레이션 (덮어쓰기 안전 가드 포함).

## 6. 검증 필요 항목 (수동 테스트)

1. **sync 정상**: 두 기기 모두 Chrome 로그인 → A에서 도메인 OFF → B 새로고침 → B에도 도메인 OFF 적용
2. **quota fallback**: 개발자 콘솔에서 `chrome.storage.sync.QUOTA_BYTES_PER_ITEM` 한도 초과 데이터 주입 → safeSyncSet이 local에 저장 + popup이 fallback 메시지 표시
3. **migration**: v0.3.0 사용자가 v0.4.0 업데이트 시 → onInstalled(update) → migrateLocalToSync 실행 → sync에 데이터 없으면 local→sync 복사. sync에 이미 데이터 있으면 skip.
4. **동기화 비활성화**: chrome://settings/syncSetup에서 확장 프로그램 sync OFF → popup에서 sync 사용량 0 또는 "사용 불가" 표시. 데이터는 local에만 유지.
5. **storage.onChanged cross-area**: 기기 A에서 sync 데이터 변경 → 기기 B content.js가 'sync' area onChanged 감지 → resolveAndApply 호출.
