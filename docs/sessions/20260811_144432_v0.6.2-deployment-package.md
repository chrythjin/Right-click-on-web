# v0.6.2 배포 패키지 생성

## 결과

- 기존 배포 산출물 `right-click-on-web-v0.6.1.zip`, `right-click-on-web.zip`을 제거했다.
- Chrome Web Store 업로드용 `right-click-on-web-v0.6.2.zip`을 생성했다.
- 저장소 루트에는 최신 배포 산출물 하나만 남겼다.

## 패키지 구성

ZIP에는 다음 13개 파일만 포함했다.

- `manifest.json`
- `shared.js`
- `background.js`
- `content.js`
- `content-main.js`
- `popup.html`
- `popup.css`
- `popup.js`
- `options.html`
- `options.css`
- `options.js`
- `icons/icon128.png`
- `icons/icon512.png`

문서, 테스트, 개발 도구 설정, 저장소 메타데이터, 미리보기 파일은 포함하지 않았다.

## 검증

- `manifest.json`은 유효한 JSON이며 Manifest V3, 확장 버전 `0.6.2`로 확인했다.
- 배포 대상 JavaScript 6개의 `node --check`가 모두 통과했다.
- ZIP의 모든 파일을 현재 작업 트리 원본과 SHA-256으로 비교해 내용이 일치함을 확인했다.
- 필수 파일 누락과 허용 목록 외 파일이 없음을 확인했다.
- 패키지 크기: 37,787바이트
- 패키지 SHA-256: `6e73321d1dfb9ce883d0f8ac0d2702161bfb3ab7ab38bbfc391696b6bed649f0`

AI 변경 검토는 패키징 차단 결함을 보고하지 않았다. 제안 9건은 오류 안내 유지,
통계 미러의 신뢰 경계, 재스캔 간격, 향후 호출 계약 방어 등 기존 미커밋 소스에 대한
후속 개선 사항이었다. 이 중 가장 높은 심각도 항목도 현재 호출 목록이 모두 `on*`
이벤트 속성인 상태에서는 재현되지 않는 미래 호출 계약 위험이므로 배포 소스를 추가로
변경하지 않았다.

실제 우클릭·선택·복사 해제 동작은 앞선 관리형 브라우저 검증에서 저장소 스크립트를
매니페스트 순서로 실행해 확인했다. 다만 Chrome Web Store 심사 환경과 사용자의 일반
Chrome 프로필에 설치한 배포 ZIP의 주입 상태는 자동화 환경에서 직접 증명한 범위가 아니다.
